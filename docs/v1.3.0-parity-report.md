# Life Launcher Web Demo v1.3.0 Parity Audit

## Decision

**DEFERRED — NOT READY FOR A SIMULTANEOUS v1.3.0 WEB DEPLOY**

The current Web Demo remains functional and safe to keep at its existing production version, but it does not yet satisfy the Windows v1.3.0 Main interaction contract. This does not block the Windows v1.3.0 release. No production deployment was performed.

Audit branch: `release/v1.3.0-parity-audit`

Audit base: `9212c0c` (`feat: sync early completion choice in web demo`)

## Verified current parity

The current Demo already provides:

- Project-backed NextStep sample sources.
- Wishlist sources with stable item IDs.
- Stable `sourceId` identity for Today snapshots.
- Same-text Wishlist items remaining distinct by ID.
- Today3 maximum of three items.
- Duplicate adoption guard.
- Removing a Today item while retaining its source.
- Timer, pause, completion, early-completion, and activity simulation.
- Project color dots/labels on several source and Today surfaces.
- A transient Do Now candidate index that does not rewrite canonical source data.
- Versioned `localStorage` validation, stable-ID normalization, and failure fallback.
- Keyboard focus rings and global reduced-motion handling.
- No analytics, backend, account, network API, Tauri package, or real user data.

## Blocking parity gaps

| Required v1.3 contract | Current Demo | Result |
| --- | --- | --- |
| Today Picker with destination slots above and NextStep/Wishlist sources below | Permanent `今日を組み立てる` disclosure section | FAIL |
| Selected source omitted from the Picker source list | Selected source remains visible as a disabled Builder row | FAIL |
| `＋ 今日へ` / `↩ 今日から外す` Picker grammar | Old `今日へ` and candidate-exclusion Builder grammar | FAIL |
| Project creation flow | Projects are seed-only | FAIL |
| NextStep setup flow | NextStep changes only through completion flow | FAIL |
| Wishlist grouped by Project | Wishlist items have no Project identity | FAIL |
| NextStep/Wishlist source lock and `✓ 今日の3件` state | No source lock presentation | FAIL |
| Do Now `他の一手` wording and complete Project-color follow | Uses `別の候補`; label changes, card accent remains fixed green | FAIL |
| No stale Project color after candidate rotation | No dedicated stale-color assertion | FAIL |

| Disabled controls never lift | Covered for some controls, not the complete v1.3 matrix | PARTIAL |

Because these gaps affect the information model and primary adoption flow, they should be implemented as a dedicated Web Demo feature change rather than hidden inside the Windows release audit.

## Project color findings

Current semantic color use is partial:

- PASS: Project labels use amber, green, blue, or violet.
- PASS: Today cards derive their accent from the associated Project.
- PASS: Timer green/blue semantics are not overwritten by Project colors.
- FAIL: the Do Now card has a fixed green left border instead of deriving the active candidate Project color.
- FAIL: no automated test proves every Project-colored ornament switches together without stale color.

## Interaction grammar findings

Current CSS has visible `:focus-visible`, hover, disabled, and `prefers-reduced-motion` rules. The current tests also verify keyboard operation and reduced motion. It is not yet the complete v1.3 Main matrix:

- Gold, neutral, positive, and timer actions exist and remain visually distinct.
- Focus is discoverable without relying only on color.
- Reduced motion removes transitions globally.
- The old Builder and generic button pressed behavior do not match the frozen v1.3 Main contract closely enough for parity acceptance.

## localStorage compatibility

The Demo uses `life-launcher-web-demo:v2` and validates parsed data before accepting it. Invalid data falls back without writing corrupted state. Today items without `sourceId` receive a deterministic legacy identity. The future v1.3 Web sync should add a new versioned decoder that:

1. adds Project identity to legacy Wishlist rows,
2. preserves existing stable Wishlist IDs,
3. preserves Today source identity and maximum-three validation,
4. removes the obsolete permanent Builder view state without clearing user content,
5. writes the new schema only after successful decoding.

No destructive storage reset was introduced during this audit.

An initial visual run was incorrectly executed in parallel with E2E. Both suites shared port 4173, so two visual cases received `ERR_CONNECTION_REFUSED` after the competing server exited. The visual suite passed all 16 cases when rerun alone; this was an audit orchestration error, not a product failure.

## Security maintenance

Vitest was updated from the vulnerable 3.x range to patched `4.1.11`. This removes the `@vitest/mocker` path traversal advisory reported by npm audit. Unit, E2E, visual, lint, build, and public safety checks continue to pass.

## Deliberately omitted native features

The following remain Windows-only by design and are not parity gaps:

- Explorer launching and real app/file/folder/URL actions
- Tauri capabilities and native pickers
- global shortcuts, autostart, tray, and multi-window management
- filesystem backup/restore and Software Reset
- real instruction files and native recommendation logic
- OS notifications

## Required follow-up before Web v1.3 deployment

1. Add Project identity to Wishlist and a non-destructive v2-to-v3 localStorage migration.
2. Add Project creation and NextStep setup interactions.
3. Replace the permanent Builder with the frozen Today Picker contract.
4. Add source-lock UI and Project-grouped Wishlist rows.
